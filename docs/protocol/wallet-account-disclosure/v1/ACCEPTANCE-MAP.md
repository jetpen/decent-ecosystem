## Owner adoption recorded for this normative profile

- Signup disclosure uses an RP-authenticated continuation only after successful OIDC processing at the RP. This is a relying-party trust model; there is no cryptographic proof of RP behavior delivered to the Wallet. A Keycloak-signed completion receipt would be a different protocol version/change.
- Account claims use a closed finite v1 allowlist of owner-asserted strings. Optional claims may be omitted only when user-approved/requested; all required fields are mandatory.
- OID4VP uses a project-defined self-issued account credential JWS inside a distinct Ed25519 Owner-Key-signed VP JWS, plus `x509_san_dns` RP identity, static discovery audience, DCQL and `direct_post`.
- Binding statement is a Keycloak-realm-signed RS256 JWS nested in the OIDC ID token; owner public JWK and RFC 7638 thumbprint are included.
- Explicit `signup` creates a new Keycloak-local principal only when the exact principal does not already exist; an existing principal fails signup without authentication or disclosure. `signup_recovery` is a distinct fresh-proof action for an enabled existing exact principal when the RP account is absent; disabled principals remain blocked. It creates no Keycloak principal and is not general login/recovery.
- Each RP declares open or closed signup. Open permits account creation without administrator approval; closed accounts remain pending and inaccessible until site-administrator approval.
- Request/presentation/binding lifetimes are bounded to 300 seconds; `direct_post` completion uses a single-use 256-bit code with 60-second expiry.

The local-only Master Account Entity boundary and existing-principal signup rule align with the adopted architecture. The open/closed signup policy and fresh-proof recovery action are part of the adopted profile and are reflected in the live issue. Keep it open until the adopted package is merged, consumer tests pass, and independent human review evidence is recorded.

**Recovery conformance gate:** Keycloak/RP implementations must prove recovery succeeds only for a fresh, exact wallet proof of an existing Keycloak principal with no RP-local account; it must fail without disclosure for a missing/ambiguous/disabled principal or an already-existing RP account. No consumer test has run yet.
